# 核心与鸣潮资源包的执行计划接口

在资源仓库根目录运行 `python3 -B -m Github wuthering-waves plan <操作>`（`install`、`update`、`switch` 或 `uninstall`），根据配置、固定快照及本机状态样例验证动作语义。正常输出写 stdout 或 `-o` 指定的文件，失败写 stderr 并返回非零。终端用户侧只读[客户端交付清单](../../Game/Wuthering%20Waves/manifests/package.json)中的数据。

## 输入

`--state` 是核心提供的 JSON 文件。空目录首次安装可省略。下列字段中的文件记录均使用游戏内相对路径、字节大小和小写 MD5。

| 字段 | 语义 |
| --- | --- |
| `installed` | 核心上次成功执行后保存的回执。包含 `game`、`channel`、`quality`、`version`、各包的 `packs` 版本映射、`files` 所有权记录。当前计划的 `receipt` 是其模板 |
| `files` | 核心现场核验的文件数组，每项有 `path`、`size` 和 `md5`。省略某条即表示此文件缺失，应覆盖目标文件、补丁所需旧文件及已装回执中可能退休的路径 |
| `cache` | 按渠道组织的缓存。例如 `cache.bilibili` 内含 `version` 和核验过的 `files` 数组。缓存记录需与目标主、次版本匹配 |
| `installed.risk_applied`、`originals` | 核心已登记风控改动时设置前者。后者列出核心能从回执恢复且已校验的原件，脚本按恢复后的内容计划。核心实际执行前需再次确认回执对应的状态 |
| `capabilities` | 核心支持库洛差分应用时传 `["krpdiff"]`。可通过 `--full-files` 显式指定只使用整文件差额 |
| `staged` | 核心暂存区中已校验的传输物，每项有 `size`、`md5`。预下载后再次规划时仍可复用，暂存命中不计入网络字节数 |

在本地核对完整安装的“无需下载”情形，可以把刚生成的目标回执当作一份**测试输入**。在资源仓库根目录运行以下命令。真实客户端应核验磁盘，使用实际回执。

```sh
python3 -B -m Github wuthering-waves plan install --channel cn -o /tmp/wuwa-install.json
jq '{installed: .receipt, files: .receipt.files}' /tmp/wuwa-install.json > /tmp/wuwa-simulated-state.json
python3 -B -m Github wuthering-waves plan update --state /tmp/wuwa-simulated-state.json |
  jq '{operation, download_bytes, reused_files}'
```

## 核心消费的阶段

1. **预检和暂存。** 核心核验空间与前置条件，从 `downloads` 暂存传输文件。每项有唯一的 `id`、`kind`、`url`、含同渠道镜像的 `urls`、`size`、`md5`，可选 `chunks`。输出中的 `staged` 给出已缓存的传输记录，后续动作仍可引用其 ID。总网络字节数为 `download_bytes`。
2. **准备现场。** 执行 `prepare` 的已登记风控还原与源服备份。源服、目标服和缓存均须使用各自的渠道名。所有 `patches` 的输出应暂存并校验，再进入安装动作。
3. **应用文件。** `actions` 指定安装暂存文件、恢复目标缓存、隔离源服独有文件或移除已退休的受管文件。`expect` 表示执行前必须重新核对的原文件。`preserved` 在卸载时列出仍存在的已修改受管文件。用户额外放入的文件不会进入删除计划。
4. **应用风控和登记。** 按顺序执行 `risk_control` 和 `finalize`。JSON 登记采用递归合并。仅在前面各阶段成功后提交 `receipt`。核心的回执还应记录实际进行的风控改动与登记字段的原值，供之后恢复。卸载使用本地回执，即使快照不可访问也可生成计划。

安装和普通更新逐文件检查目标内容。官服与 B 服之间的转服优先使用已校验目标缓存，对被替换且仍匹配回执的源服文件生成备份。涉及国际服时逐项校验完整目标。风控规则支持在 `sources.toml` 中按 `channels`、`qualities`、`versions` 筛选，动作和冲突语义见设计对照。当前未配置实际游戏文件的风控改动。[本机状态](../../Github/wuthering_waves/inventory.py) · [计划生成](../../Github/wuthering_waves/planner.py) · [风控规则](../../Github/wuthering_waves/rules.py) · [风控示例](源码对照.md)

## 同服更新与预下载

`update` 按回执中每个包的源版本精确查找补丁，并取固定提交中的官方原件校验其 MD5。脚本逐项检查差分输出与当前渠道完整目标表一致。源文件缺失、MD5 不符、完整文件优先或差分比直接取得目标文件更耗流量时，该组走整文件差额。`pack_strategies` 记录每个包的选择，`patches` 仅包含实际采用的分组、输入与输出。补丁传输地址、完整文件自己的 `fromFolder` 和各包的正式文件目录分别解析。所有源文件前置条件应在改变任一游戏文件前重新核对。[分包更新实现](../../Github/wuthering_waves/updates.py)

`plan update --stage predownload --state local-state.json` 要求本机选定档位的正式版已经更新。此模式返回下载清单，文件操作、风控和版本登记均为空。正式开放后重新生成正式计划，使用相同内容摘要的暂存文件。渠道尚未开放完整的预下载目标时，正式快照仍可用，可用的预下载档位取自该渠道自身发布的信息。
